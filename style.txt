C++で競技プログラミングのコードを書くときは、以下のコーディングスタイルに従ってください。

* `#include <bits/stdc++.h>` を使う。
* AtCoder Libraryを使う場合は `#include <atcoder/all>` を使う。
* `using namespace std;` は使ってよい。
* AtCoder Libraryの型や関数には、基本的に `atcoder::` を明示する。
* インデントはタブを使う。
* `if`、`for`、`while` などの制御構文では、キーワードと `(` の間に半角スペースを入れる。

  * `if (x == 1)`
  * `for (int i = 0; i < N; i++)`
* 二項演算子の前後にはスペースを入れる。

  * `a + b`
  * `x == y`
  * `i < N`
  * `f + x`
* カンマの後にはスペースを入れる。
* `{` は同じ行に置く。

  * `if (condition){`
  * `for (...){`
* `}` と `else` は同じ行にして `} else {` と書く。
* 複数行の `if` / `for` / `while` では `{}` を付ける。
* 変数名は競プロらしく短めにする。

  * `N`, `Q`, `S`, `A`, `l`, `r`, `i`, `t` など。
* 不要に長い変数名やクラス名を作らない。
* `auto &` のような型推論付き参照はなるべく使わず、明示的な型を使う。
* `vector` はサイズが明確なら最初に確保する。
* 条件演算子は短く済む場合に使ってよい。

  * `(S[i] == 'A' ? 1 : -1)`
* 論理積は `&&` ではなく `and` を使ってください。||も同様。
* 出力は基本的に `cout << ... << endl;` を使う。
* 不要なコメントは書かない。
* 空行は極力減らし、コード全体をコンパクトにする。
* 過剰な関数分割や抽象化はせず、競技プログラミングで読みやすく短い実装を優先する。
* STL・ACLで既にある機能は自前実装せず積極的に使う。
* `main` 内の処理は多少長くてもよく、単純な処理を無理に関数化しない。
* コードだけを要求された場合は、長い解説を付けず完成コードを提示する。

特に、次のような見た目を基準にしてください。

```cpp
int main(){
	int N;
	cin >> N;
	string S;
	cin >> S;
	for (int i = 0; i < N; i++){
		if (S[i] == 'A'){
			// 処理
		} else {
			// 処理
		}
	}
}
```

アルゴリズムそのものを変える必要がない場合は、このスタイルを崩さずに修正・追加してください。
